# ImmuTrack — Render + GitHub Deployment

This project is prepared for deployment as a Django web service on Render with PostgreSQL, Gunicorn, WhiteNoise, Python 3.11, Nashik dataset initialization, and ML model initialization.

## 1. Push to GitHub

The GitHub repository should contain the contents of this `immutrack_project` directory at its repository root, so these files are visible at the top level:

- `manage.py`
- `requirements.txt`
- `build.sh`
- `render.yaml`
- `.python-version`
- `immutrack/`
- `accounts/`
- `children/`
- `vaccination/`
- `notifications/`
- `analytics/`
- `data/`

Do **not** commit `.env`, passwords, or a manually created production secret key.

## 2. Deploy with Render Blueprint

In Render, create a new Blueprint and select the GitHub repository. Render will read `render.yaml` and create:

- a Python web service
- a PostgreSQL database
- `SECRET_KEY` generated by Render
- `DATABASE_URL` connected to PostgreSQL
- Python 3.11

Render will run `build.sh` during deployment.

## 3. What the build does

`build.sh` performs:

1. `pip install -r requirements.txt`
2. `python manage.py migrate --noinput`
3. `python manage.py seed_immunization_data`
4. `python manage.py import_nashik_dataset --skip-ml`
5. trains and persists the Random Forest ML model
6. generates Nashik child risk assessments
7. `python manage.py collectstatic --noinput`

## 4. Production settings

- `DEBUG=False`
- `SECRET_KEY` comes from Render's environment
- `DATABASE_URL` selects PostgreSQL
- WhiteNoise serves collected static files
- Gunicorn serves Django
- Render's hostname is accepted automatically
- HTTPS cookies/security settings are enabled in production

## 5. Start command

```bash
gunicorn immutrack.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 120
```

## 6. Important security note

The bundled Nashik dataset contains demonstration accounts with known passwords because this is an academic/demo dataset. Before using the application with real users, replace or remove those accounts and credentials.
